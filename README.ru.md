# TeamWork

> **Раскрытие использования ИИ:** проект создан при помощи **OpenAI Codex (GPT-5)**. Владелец проекта проверил и принял реализацию и документацию.

TeamWork периодически получает задачи Jira через авторизованный Docker MCP Gateway, группирует их, создаёт Markdown-документ и показывает его в веб-интерфейсе, похожем на редактор.

## Возможности

- Интеграция с Docker MCP Gateway без хранения Jira-токенов в конфигурации.
- Настраиваемая иерархия: Goal → тема → активный спринт → будущий спринт → бэклог.
- Периодическая и ручная синхронизация.
- Структура документа, поиск, scroll-spy и вложенное сворачивание разделов.
- Значки типов и статусы задач в заголовках.
- Локальные комментарии под заголовками задач и панель управления ими.
- Независимое хранение комментариев и удаление записей исчезнувших задач.
- Структурированные JSONL-логи и просмотр журнала в интерфейсе.

## Требования

- Docker Desktop с включённым MCP Toolkit; рекомендуется версия 4.62 или новее.
- Профиль Docker MCP с авторизованным сервером Atlassian.
- Node.js 22+ для локальных проверок вне Docker.

## Настройка и запуск

```bash
cp grouping.config.example.json grouping.config.json
```

Укажите Atlassian cloud ID, проект, JQL, поле спринта, правила группировки и расписание. Реальный `grouping.config.json` исключён из Git, поскольку может содержать внутренние идентификаторы.

По умолчанию используется профиль `ecom_2_0`. Его можно изменить без правки файлов:

```bash
MCP_PROFILE=my_profile ./start.sh
```

Скрипт создаёт временный bearer-токен Gateway и передаёт его только через окружение процессов и контейнера. В macOS долгоживущим Gateway управляет `launchd`, поэтому закрытие терминала не останавливает синхронизацию. Временный файл передачи с правами `0600` удаляется сразу после чтения. OAuth Atlassian остаётся под управлением Docker Desktop.

На системах не macOS доступен запуск под внешним супервизором:

```bash
MCP_GATEWAY_FOREGROUND=1 ./start.sh
```

После запуска откройте <http://localhost:8080>.

Для создания или пересоздания контейнера всегда используйте `./start.sh`. Прямой `docker compose up` намеренно блокируется: он не может передать временный токен MCP Gateway и оставил бы приложение с ошибкой `401 Unauthorized`. Для просмотра состояния используйте веб-интерфейс или Docker Desktop.

### Сетевой доступ и авторизация

По умолчанию Compose публикует сервис только на `127.0.0.1`. Для доступа из доверенной сети явно включите Basic Auth и измените адрес:

```bash
APP_BIND_ADDRESS=0.0.0.0 \
APP_AUTH_USER=owner \
APP_AUTH_PASSWORD='длинный-случайный-пароль' \
./start.sh
```

Не публикуйте сервис в интернете без HTTPS-прокси. Пароль передаётся только при запуске и не должен попадать в Git.

## Локальные данные

Документ, комментарии, логи и PID-файлы находятся в `data/` и не публикуются. Комментарии не отправляются в Jira и не добавляются в Markdown.

## Разработка и безопасность

```bash
npm ci
npm run check
docker compose build
```

В GitHub Actions включены синтаксические и функциональные тесты, `npm audit`, CodeQL и dependency review. Контейнер работает без root, с read-only root filesystem, сброшенными capabilities, `no-new-privileges` и healthcheck. Пути документов ограничены каталогом `data/`. Dependabot, secret scanning, push protection, приватные отчёты об уязвимостях и автоматические security updates включены в репозитории. Подробности — в [SECURITY.md](SECURITY.md).
